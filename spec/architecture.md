# アーキテクチャ決定事項(プロトコル仕様)

このドキュメントは kagemiru-host / kagemiru-client に限らず、Kagemiru
プロトコルと互換な実装(他のホスト・クライアント)が満たすべき事項を定める。
プラグイン単体の実装詳細(内部設計・DBスキーマ等)は各リポジトリの
`spec/` を参照。

## 通信方向

| 対象データ | 方向 | 理由 |
|---|---|---|
| セキュリティ設定・ログイン履歴・更新状態 | クライアント→ホスト(Push) | CloudSecure等がREST APIを無効化することがあり、ホスト側の受信APIに影響を与えないため |
| 死活監視 | ホスト→サイト(Pull) | サイトがダウンしている間はクライアント側の送信処理自体が動かないため、外形監視は独立させる必要がある |

## 認証

- サイトごとに個別の連携キーを発行する(全サイト共通キーにしない)
- 生キーをリクエストに載せず、HMAC-SHA256署名をヘッダーで検証する
- リクエストヘッダー・署名対象は [data-schema.md](./data-schema.md) を参照

## 相互接続性の位置づけ

kagemiru-host と kagemiru-client は同一の構想の下で開発されるが、それぞれ
独立したプロダクトとして管理する。

- kagemiru-host は、本プロトコルに準拠していれば kagemiru-client 以外の
  クライアント実装からのレポートも受理可能とする
- kagemiru-client は、本プロトコルに準拠していれば kagemiru-host 以外の
  送信先を設定することも妨げない
- 「Kagemiru」として相互接続性を保証するのは kagemiru-host /
  kagemiru-client の組み合わせのみであり、本ドキュメントが定める内容が
  その保証範囲(プロトコル)にあたる
